# Fwknop — Single Packet Authorization client

Cross-platform (Android/iOS) [fwknop](https://www.cipherdyne.org/fwknop/) SPA
client built with Flutter. Sends an encrypted, HMAC-authenticated Single Packet
Authorization packet (default: UDP/62201) to a `fwknopd` server to open
firewall access (e.g. `tcp/22`) for your source IP.

## Usage
1. Add a profile: server host/port, access request (`tcp/22`), and the
   `KEY` / `HMAC_KEY` from the server's `access.conf` (base64, as shown by
   `fwknop --key-gen`).
2. Tap send. The app resolves your public IP (or uses a manual/spoofed one),
   builds the SPA packet with libfko-compatible encoding (AES-CBC + SHA256
   digest + optional HMAC-SHA256) and fires it over UDP.

No reply comes back by design — check that you can now connect, or watch
`fwknopd` logs on the server.

## Protocol implementation
`lib/fko.dart` implements the client side of the FKO protocol
(`fko_encode.c`/`fko_encryption.c`/`fko_hmac.c`/`cipher_funcs.c` from
https://github.com/mrash/fwknop): AES in OpenSSL-compatible CBC mode
(EVP_BytesToKey/MD5 salt+IV derivation, `Salted__` prefix), SHA256 digest,
optional encrypt-then-MAC HMAC (md5/sha1/sha256/sha384/sha512, like
`fwknop --hmac-digest-type`), wire format with the constant `U2FsdGVkX1`
prefix stripped.

Verified against the real toolchain (`flutter test`):
- round-trip decode of generated packets,
- decoding a packet generated by the official `fwknop` CLI,
- the generated packet decrypts and HMAC-verifies inside the real `libfko`
  (see `bin/gen_spa.dart` + any libfko decoder).

## Build
```sh
flutter test
flutter build apk --split-per-abi   # Android (minSdk 30)
flutter build ios                   # iOS (needs full Xcode)
```

`--split-per-abi` writes `app-{armeabi-v7a,arm64-v8a,x86_64}-release.apk` to
`build/app/outputs/flutter-apk/` rather than one universal APK. Native libraries
are ~94% of the download and are stored uncompressed (`extractNativeLibs` is
false at minSdk 23+), so splitting is the main size lever:

| APK | size | versionCode |
|---|---|---|
| `app-arm64-v8a-release.apk` | 19.2 MB | 2001 |
| `app-armeabi-v7a-release.apk` | 16.7 MB | 1001 |
| `app-x86_64-release.apk` | 20.7 MB | 4001 |

Install the arm64-v8a APK on any modern device. Flutter adds `1000 * ABI_VERSION`
to the pubspec version code for split APKs, hence the codes above. For a Play
upload use `flutter build appbundle`, which lets the store serve per-device
splits.

Building requires Flutter 3.47+ (targetSdk 36), which in turn requires Gradle
9.3.1, AGP 9.1.0, Kotlin 2.4.0 and Java 17. The Android NDK matching
`flutter.ndkVersion` is downloaded automatically on first build.

## Storage & privacy
Profiles — including the `KEY` / `HMAC_KEY` from `access.conf` — are stored
only on the device, in Android Keystore-backed encrypted storage or the iOS
Keychain (non-migratable, not synced to iCloud Keychain). Android cloud backup
and device-to-device transfer are disabled so keys are never uploaded.

The one third-party disclosure is public-IP resolution: with "Auto-resolve
source IP" on (the default), the app queries `api.ipify.org` / `icanhazip.com`
before sending. Turn it off and set a source IP manually to avoid that.
See [PRIVACY.md](PRIVACY.md).
